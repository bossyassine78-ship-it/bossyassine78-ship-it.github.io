The attack surface

The server has three sample identities (Alice, Bob, Admin), two orders, and a privileged invitation function. In vulnerable mode, it treats successful authentication as proof of authority. In fixed mode, each decision checks the correct invariant.

01 / Deleted-account token still works

Invariant: a deleted account must no longer authorize protected operations.

DELETE /api/me HTTP/1.1
Authorization: Bearer alice-demo-token

HTTP/1.0 200 OK
{"deleted":"alice"}

GET /api/me HTTP/1.1
Authorization: Bearer alice-demo-token

VULNERABLE: 200 OK (deleted user returned)
FIXED: 401 UNAUTHENTICATED

Root cause: treating presence of a historical token as sufficient authorization, without checking the current account state. Acquiring someone else's token is a separate exploitability requirement; this demonstration does not claim a remote ATO.

02 / IDOR / BOLA against another user's order

Invariant: an authenticated user cannot retrieve another user's resource unless their permissions explicitly allow it.

GET /api/orders/4002 HTTP/1.1
Host: 127.0.0.1:8765
Authorization: Bearer alice-demo-token

VULNERABLE HTTP/1.0 200 OK
{"order":{"id":"4002","owner":"bob","item":"Keyboard","total":60}}

FIXED HTTP/1.0 404 Not Found
{"error":"NOT_FOUND"}

Root cause: object lookup performed after token validation but without ownership validation. In fixed mode, only the owner or explicit admin may read the resource.

03 / Broken function-level authorization

Invariant: only administrators can create an administrator invitation.

POST /api/admin/invitations HTTP/1.1
Host: 127.0.0.1:8765
Authorization: Bearer alice-demo-token
Content-Type: application/json

{"email":"new-admin@lab.invalid"}

VULNERABLE: HTTP 201 (role: admin)
FIXED: HTTP 403 {"error":"FORBIDDEN"}

Root cause: server checks whether the caller is signed in but not whether they have permission to invoke the function. This is BFLA rather than mass assignment.

Source code & reproducibility

The lab provides an isolated server.py, deterministic fixtures, --mode vulnerable|fixed, and automated HTTP regression tests. Run exactly the same requests against both modes to verify the invariant.

cd labs/authz-lab
python3 server.py --mode vulnerable

# In a second terminal:
curl -i -H 'Authorization: Bearer alice-demo-token' \
http://127.0.0.1:8765/api/orders/4002

# Automatic tests, in the lab directory:
python3 -m unittest -v test_lab.py

For the complete copy-paste commands and tests, read the source repository README inside labs/authz-lab/.

Research standard

Every case distinguishes an unexpected response, a reproducible unauthorized outcome, and the limitations of the exploit chain. The fix is not merely an error message: it enforces a state or ownership invariant at the actual server-side operation.
