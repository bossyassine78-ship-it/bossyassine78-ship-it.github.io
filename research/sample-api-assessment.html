ORIGINAL API SECURITY LAB / REPORT 001

Authorization assessment: from evidence to retest.

A complete technical assessment of a localhost API that I built with intentional authorization defects. The service, users, tokens and data are fictional. This is not a client assessment or evidence of a real company's vulnerability.

Scope: `http://127.0.0.1:8765` · Python standard-library server · three test principals (Alice, Bob, admin) · two orders · privileged invitation function. Every scenario has vulnerable and fixed modes.

01 / Broken object-level authorization

Finding: a valid user credential can retrieve a different account's order without ownership validation.

GET /api/orders/4002 HTTP/1.1 Host: 127.0.0.1:8765 Authorization: Bearer alice-demo-token HTTP/1.0 200 OK Content-Type: application/json {"order":{"id":"4002","owner":"bob","item":"Keyboard","total":60}}

Expected: Alice must not access Bob's record. Root cause: an authentication check without a resource ownership check. Fix: enforce object owner or explicit administrator role at the server-side lookup. Retest: HTTP 404 with {"error":"NOT_FOUND"}.

02 / Broken function-level authorization

Finding: a member can invoke the administrator invitation function because login state is mistaken for admin privilege.

POST /api/admin/invitations HTTP/1.1 Host: 127.0.0.1:8765 Authorization: Bearer alice-demo-token Content-Type: application/json {"email":"new-admin@lab.invalid"} HTTP/1.0 201 Created

Expected: only an admin can create an admin invitation. Fix: enforce action-specific role authorization. Retest: HTTP 403 with {"error":"FORBIDDEN"}.

03 / Deleted-account credential reuse

Finding: the authentication guard accepts a known demo token even when its associated account has been marked deleted.

DELETE /api/me HTTP/1.1 Authorization: Bearer alice-demo-token HTTP/1.0 200 OK {"deleted":"alice"} GET /api/me HTTP/1.1 Authorization: Bearer alice-demo-token VULNERABLE: 200 OK FIXED: 401 Unauthorized

Expected: deleted identities no longer authorize requests. Fix: account-active checks plus complete credential revocation. Impact limitation: a remote attacker obtaining another person's token has not been demonstrated, and this lab is not a claim of account takeover.

Reproduction and verification
