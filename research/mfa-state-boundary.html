A session is not the same as completed authentication

An MFA bypass case illustrates a common mistake: granting server-side authority while a second factor is still pending.

By Shemkar · Independent analysisPublic source: Nov 20246-minute read
Attribution and scope. Analysis of HackerOne's public November 2024 write-up describing a report submitted by akhan8041 in January 2024. The original finding is not mine. This page is my own commentary and testing framework based on public information, not a claim that I discovered or reproduced the original vulnerability. All hypothetical tests refer to systems where testing is authorized.

What the source establishes

HackerOne publicly documented an MFA-bypass case in which a website issued authenticated session material before its email-based one-time-code step was complete. According to the write-up, client-side state controlled the apparent checkpoint, so changing cookie state let a user proceed without passing MFA.

The server-side mistake is larger than a removable cookie: session authority and authentication completion were not the same state.

My model: three stages, not two

ANONYMOUS → PASSWORD_VERIFIED → MFA_VERIFIED

Allowed sensitive actions:
only when state == MFA_VERIFIED

A useful regression suite asserts that every sensitive route rejects the middle state. A valid password may establish a temporary authentication challenge, but it should not authorize actions that require an MFA-complete session.

Controlled test questions

  • Which session artifacts are issued after password verification but before OTP verification?
  • Can the application load protected data in the middle state, even if the UI still shows the OTP prompt?
  • Does removing or modifying a client-controlled cookie change the server's interpretation of completed authentication?
  • Do REST, GraphQL, mobile, and legacy endpoints consistently enforce the MFA-complete predicate?
  • Are refresh tokens prevented from upgrading a partially authenticated session?

Impact and evidence discipline

A response containing an identifier is not automatically an MFA bypass. The meaningful proof is an action or protected resource that server policy says must require the second factor. Demonstrate that action in a controlled test account, and identify the exact precondition and resulting access.

Engineering takeaway

Make MFA completion a server-side property, not a UI convention. Generate full-authority credentials only after factor completion; ensure refreshing, rotating, or upgrading a session cannot skip the transition.
